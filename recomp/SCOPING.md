## HLE(네이티브 재구현)가 필요한 것

### 1. DOS 서비스 (`int 21h`, 87곳)
파일 I/O(3Ch 생성, 3Dh 열기, 3Eh 닫기, 3Fh 읽기, 40h 쓰기, 41h 삭제, 42h 탐색, 43h 속성, 44h IOCTL),
메모리(48h/49h/4Ah), 날짜·시간(2Ah/2Ch), 버전(30h), 인터럽트 벡터(AH=25h 29곳, 35h 4곳 — **대부분은
Watcom CRT의 Phar Lap 익스텐더용 `AX=2502h~250Ch` 경로**이고 DOS/4GW에서 실제로 설치되는 벡터는
아래 "플랫폼 훅 상세"의 표에 정리), 종료(4Ch), 그 외. AH=EDh 1곳은 정체 미확인.
→ 대부분 Watcom CRT의 파일·메모리 함수 안에 있으므로, CRT 함수 단위로 바꾸거나 `int 21h` 디스패처 하나로 처리하면 됩니다.

### 2. DPMI (`int 31h`, 47곳 + `int386()` 경유 12곳)
LDT 디스크립터(0000h/0006h~0009h), 실모드·보호모드 인터럽트 벡터(0200h/0201h/0204h/0205h),
실모드 인터럽트 시뮬레이션(0300h), 실모드 콜백(0303h/0304h), 메모리 잠금(0600h), 버전(0400h).
→ 대부분 ISR 설치와 DOS 메모리용입니다. 셀렉터는 "셀렉터 → 베이스" 테이블 하나로 모델링하면 됩니다.

### 3. 하드웨어
| 장치 | 증거 | 대체 방법 |
|---|---|---|
| VGA 모드 13h | `int 10h AH=00h/0Fh`, DAC `out 3C8h` + `3C9h` | 0xA0000 프레임버퍼 → SDL 텍스처 + 팔레트 |
| 시간 | Watcom `clock()` ← `intdos(AH=2Ch)` (DOS 시각, 1/100초). 게임 자체의 타이머 ISR은 없음 | `int 21h/2Ch`를 호스트 시계로 응답 |
| 마우스 | `int 33h` 0000h/0007h/0008h + **000Ch 이벤트 콜백 `0x30820`** (마스크 1Fh) | SDL 이벤트 → 콜백 호출 |
| 키보드 | **ISR `0x308F0`을 int 09h에 설치**(`0x30BA4`), `inp(60h)` + `61h` 응답 + EOI | SDL 키 → 스캔코드로 ISR 호출 |
| 사운드 | **Miles AIL 3** (`"AIL3DIG"`/`"AIL3MDI"` 검사, XMIDI 파서), 실모드 드라이버를 INT 66h로 호출, 타이머(int 08h)와 카드 IRQ를 AIL이 소유 | **Blizzard 사운드 래퍼(진입점 14개)를 SDL로 대체** → AIL 전체가 죽은 코드 |
| 네트워크 | IPX(DPMI 실모드 인터럽트), 모뎀 UART + 자체 시리얼 ISR(`0x1FE8C`), 16:32 far 포인터(`lgs`/`gs:` 47곳) | 1차 목표에서는 스텁 처리 |

### 4. 재컴파일러가 특별 취급해야 하는 코드 패턴
- **`int386()`/`int386x()`** (`0x33810`/`0x33C45`→`0x3CC18`): 벡터×3으로 `int N; ret` 스텁 256개 테이블(`0x3CCF6`)의 주소를
  계산해서 `push`/`ret`으로 점프함 → 함수 통째로 HLE.
- **`intdos()`** (`0x3F9D8`): REGS 포인터를 eax로 받아 `int 21h` 실행 → 같은 방식으로 HLE.
- **ISR 트램펄린** (`0x376B8`): 자리표시 즉시값 `0x9999`에 셀렉터와 스택을 써 넣은 뒤(SMC 6곳) `retf`/`iretd`로 체이닝.
  AIL의 IRQ 설치 함수(`0x3770D`) 안에 있으므로 AIL을 대체하면 함께 사라짐.
- **코드 안의 데이터**: 문자열(예: `"listen"`, `"con"`), 함수 포인터 테이블(`call [ebx*4+0x3D0CC]`), 스타트업의 DS 저장 변수.
- **Watcom 레지스터 호출 규약**(eax, edx, ebx, ecx 순)과 일부 어셈블리 루틴의 스택 규약이 섞여 있음 → 레지스터 상태를 구조체로 들고 다니는 기계 수준 리프팅이면 문제없음.

실행하는 분기라 DOS/4GW에서는 실행되지 않습니다.

### 게임의 시간원

게임 루프(`0x197B8` 등 10곳)는 `0x306DA` → `0x3B029`(Watcom `clock()`)를 호출합니다. 동작은 이렇습니다:
- `0x3AFC3`이 `intdos(AH=2Ch)`로 DOS 시각을 읽어 `((시×60+분)×60+초)×100+1/100초`로 바꿉니다.
- 시작 시각을 빼고, 자정을 넘으면 `0x83D600`(= 8,640,000 = 하루의 1/100초 수)을 더합니다.

**게임 자체의 타이머 ISR은 없습니다.** int 08h는 AIL이 겁니다. 용도는 AIL 자체의 드라이버 서비스 타이머
(초기화 `0x33CE7` → `0x3796F`)와, 게임이 등록하는 음악 페이드 아웃 콜백(`0x267BC` → `0x26F04`) 두 가지입니다.
대체 구현은 `int 21h/2Ch`를 호스트 시계로 응답하면 됩니다. 실제 DOS는 이 값을 약 18.2Hz로만 갱신하므로,
더 촘촘한 값을 돌려줬을 때 게임 속도나 프레임 페이싱이 달라지는지는 **런타임 확인이 필요**합니다.

### 사운드 스택

```
게임 코드 (효과음·음악 요청)
  └─ 음악/효과음 관리자   0x25D60–0x26158

            └─ Miles AIL 3   0x2F4B8–0x2FCA0 (DPMI 헬퍼) + 0x33C5E–0x39A00   함수 105개
```

- AIL 진입점 27개는 **전부 래퍼에서만** 호출됩니다. 예외는 CRT(`0x3F0CC`)가 공유 DPMI 잠금 헬퍼 `0x2F5AB`를 부르는 1곳뿐입니다.
- 래퍼에서 가장 많이 불리는 `0x26B5C`(호출자 10곳)는 효과음 슬롯 4개(`0x59F30 + i×8`)를 모두 정지·해제합니다.

## 이 분석의 한계

- **함수 경계는 근사값**입니다. "다음 함수 시작까지"로 크기를 재므로 최대 7,589B 같은 값에는 함수 여러 개가 합쳐졌을 수 있습니다.
- **즉시값으로 쓰인 코드 주소**가 함수인지 코드 안 데이터인지는 데이터 흐름 없이는 구분할 수 없습니다.
  문자열(3자 이상 + NUL)과 역참조된 주소는 걸러내지만, `0x18768` 같은 데이터 테이블은 여전히 함수로 잡힙니다.
- 미참조 함수 93개는 Watcom이 오브젝트 모듈 단위로 링크해서 딸려 온 죽은 코드로 보이지만, **계산된 주소로만 호출되는 함수일 가능성을 배제하지 못했습니다.**
- `int386`/`int386x`/`intdos` 호출 25곳 중 1곳(AIL의 메모리 잠금 루프 `0x2F5FE`, 손으로 확인 시 DPMI 0600h)과
  포트 접근 34곳(모뎀 UART 31곳 = 포트 베이스가 변수, AIL 3DAh 2곳, 팔레트 3C9h 1곳)은 정적으로 해석되지 않았습니다.
- `platform_map.py`의 상수 전파는 직선 코드만 다루고 분기 합류점에서 프레임 포인터 외의 정보를 버립니다.
  Phar Lap/DOS 구분도 휴리스틱이라 CL을 모르는 `AX=250Ch` 1곳(`0x40E49`)은 "DOS 25h 벡터 0Ch"로 잘못 표시됩니다.
- 영역 경계 `0x2F000`, AIL 범위, 사운드 래퍼 범위는 호출 그래프에서 정한 근사값입니다.
- **아직 런타임으로 확인한 것은 없습니다.** 모든 결론은 정적 분석이며, DOSBox 디버거로 실제 설치 순서를 확인하면 더 확실해집니다.

## 검증

`tools/selfcheck.py`가 `war.exe`와, 같은 툴체인으로 만든 두 번째 LE 파일인 `setup.exe`에서 다음을 확인합니다(현재 전 항목 PASS):

- 디코딩된 명령어끼리 겹치지 않음
- 모든 직접 분기(call/jmp/jcc) 대상이 명령어 시작점
- switch 테이블 대상 전부 디코딩됨
- 데이터 안 코드 포인터 245개가 전부 명령어 시작점 → **fixup 대상 오프셋이 정확함**
- 코드 안 fixup 7,465개 중 명령어 경계에 걸친 것 0개 → **fixup 소스 오프셋이 정확함**
- 데이터→데이터 문자열 포인터 391/391개가 문자열 시작을 가리킴

커버리지(정보 항목): war.exe 코드 fixup의 96.8%가 디코딩된 명령어나 테이블 안에 있습니다.
setup.exe는 86.3%인데, 나머지는 죽은 라이브러리 코드, 코드 안 포인터 테이블, UI 문자열 덩어리입니다(직접 확인함).

`clock()`의 AH=2Ch, 포트 60h/3C8h/43h, REGS 래퍼가 `intdos` 하나뿐임)를 도구 결과와 대조합니다(20/20 통과).
테스트가 실제로 결함을 잡는지는 변이 시험으로 확인했습니다. 프레임 포인터 유지와 바이트 단위 REGS 조합을 각각 되돌리면
각각 2건, 1건이 실패합니다.
